# task_sync_app

日本語で書いたタスクの行から、**期限**と**カテゴリ**を自動で取り出すアプリです。
スマホのホーム画面に追加して使える PWA（ウェブアプリ）と、解析を行う API（FastAPI）でできています。

## できること
- タスクを1行ずつ貼り付けると、行ごとに「題名・期限・カテゴリ」と、期限をどう読んだか・要確認の印を表示します。
- カテゴリはキーワードで4つ（寺院関係・所属団体2つ・個人）に分けます。どれにも当たらなければ「個人」です。
- Google カレンダーへの登録は、まだ画面からはできません（`/api/sync-calendar` は未実装の応答を返します）。

## 期限の書き方
行の中に、丸括弧で期限を書きます。例: `資料作り (3/15まで)` → 題名「資料作り」・期限 3/15。

- 括弧は半角 `( )` でも全角 `（ ）` でもかまいません。数字と `/` も全角で読めます。
- 期限の部分は題名から除きます。期限と関係のない括弧（`(第2版)` など）は題名に残します。
- 1行は500文字まで、一度に解析できるのは200行までです。
- 読み方の正本は `backend/task_sync/date_rules.py` です。画面・API と、カレンダー同期用の `backend/task_sync/` が同じものを使います。
- 全部の例（154件）は共通検算表 `tests/fixtures/due_cases.json` にあります。

下の表の例は、今日が **2026-10-01（木）** のときです。

| 書き方 | 読み方 | 種類（due_type） | 例 |
|--------|--------|------|------|
| `(3/15まで)` `(3/15)` `(3月15日まで)` | その日。年は下の「年の決め方」 | exact | 2027-03-15 |
| `(2026/3/15)` `(2026年3月15日)` `(2026-03-15)` | 書いた年のその日 | exact | 2026-03-15（期限切れ） |
| `(令和8年12月1日)` `(R8.12.1)` | 和暦（令和・平成・昭和） | exact | 2026-12-01 |
| `(5日まで)` | 日だけ。今日以降なら今月、過ぎていれば翌月 | exact | 2026-10-05 |
| `(5月中)` `(5月まで)` `(5月末)` | その月の末日 | month_end | 2027-05-31 |
| `(月末)` `(今月中)` `(来月末)` | 今月・来月の末日 | month_end | 2026-10-31 |
| `(10月上旬)` `(中旬)` `(下旬)` | 上旬 = 10日、中旬 = 20日、下旬 = 末日。月が無ければ今月（過ぎていれば翌月） | period | 2026-10-10 |
| `(年内)` `(年度末)` | 12/31・3/31（4月始まりの年度） | month_end | 2027-03-31 |
| `(今週中)` `(来週まで)` `(来週)` `(再来週)` | その週の日曜日（週は月曜始まり） | week | 2026-10-11 |
| `(来週火曜)` `(今週金曜)` `(再来週月曜)` | その週のその曜日 | relative | 2026-10-06 |
| `(金曜まで)` | 次のその曜日（今日と同じ曜日なら今日・要確認） | relative | 2026-10-02 |
| `(今日中)` `(今夜)` `(明日)` `(明朝)` `(明後日)` `(3日後)` `(1週間以内)` | 今日から数えた日 | relative | 2026-10-02 |
| `(至急)` / `(大至急)` | 翌日 / 今日 | urgent | 2026-10-02 |
| `(早め)` `(なるはや)` `(なるべく早く)` `(ASAP)` | 3日後 | soon | 2026-10-04 |
| `(20日以降)` `(来週から)` `(11月から)` | この日以降（期間なら始まりの日。期限切れにはしない） | after | 2026-10-20 |
| 書かない | 期限なし | none | — |

### 時刻
- `15時` `午後3時` `10時半` `9:30` `正午` を読みます。API では `due_time`（HH:MM）で返し、`deadline` は日付の 0:00 のままです。
- 午前・午後の無い 1〜6時は午後（13〜18時）と読み、要確認にします。`24時` は 23:59 にします。
- `終日` と、数字の無い `午前中` `夕方` は時刻にしません。時刻だけ（`(17時まで)`）なら今日です。

### 年の決め方（年を書かない日付）
- 今日以降の日付は今年です。
- 過ぎた日付は、**62日前まで**なら今年のまま「期限切れ」にします（定数 `PAST_DUE_GRACE_DAYS`）。それより前なら翌年です。
  - 例（今日が 2026-10-01）: `(9/30まで)` → 2026-09-30 期限切れ。`(7/31まで)` → 2026-07-31 期限切れ（ちょうど62日前）。`(7/30まで)` → 2027-07-30。
- 翌年に繰り越す月末は、その年で数えます（翌年がうるう年なら 2/29）。
- 年の初めに去年の12月の日付を書くと、今年の12月になります。去年の分は年も書いてください。

### 週の数え方
- 週は**月曜始まり**です。「来週」は、次の月曜から始まる週です。
- **日曜に書いた「来週」**は、翌日の月曜からの週です。例: 2026-10-04（日）に書くと `(来週まで)` → 10/11、`(来週火曜)` → 10/6。
  日曜始まりで数える人とは1週間ずれるので、日曜に書いた「今週・来週・再来週・週末」には要確認の印を付けます。
- `(週末)` `(今週末)` は日曜にして、要確認にします（土曜とも読めるため）。

### 要確認（needs_review）になるもの
注意（warnings）が1つでもあれば要確認です。読めない行も捨てずに返します。
- 存在しない日付（`(2/30まで)`、平年の `(2/29まで)`、`(13/1まで)`）→ 期限なし。
- 期限らしいが読めない括弧（`(文化の日まで)` `(連休明け)` `(期限未定)`）→ 期限なし。括弧は題名に残します。
- 期限切れ（上の「年の決め方」、年つきの過去の日付、`(今週月曜)` など）。
- 日付が2つ以上（`(10/5か10/6)`、括弧が2つ）→ いちばん早い日。期間（`(10/5〜10/9)` `(10月5日から9日まで)`）→ 終わりの日。
- あいまいな言葉（頃・くらい・頭・毎週 など）、月だけ（`(10月)` → 月末）、日付と曜日の食い違い（`(11/3(月))`）。
- 括弧の外の期限らしい書き方（`明日までに〜`）。読みませんが、印を付けます。
- 期限だけの行（題名が無い）。

### 読まないもの（範囲）
- **祝日の判定はしません。** `(11/3まで)` はただの日付として読み、`(11/3(祝))` の「祝」も確かめません。祝日の名前（`(文化の日まで)`）は読まずに要確認にします。
- 外部の API やカレンダーは使いません（標準ライブラリだけで計算します）。
- `(10日分)` `(2/3ページ)` のような量は期限として読みません。ただし括弧の中の `(1/2)` は1月2日と読みます。

### API の応答
`/api/parse` と `/api/parse-batch` の各行は、`title`・`deadline`（JST の 0:00）・`category`・`raw_text`・`warnings` に加えて、
`due_type`（上の表の種類）・`due_raw`（読み取った括弧の中身）・`due_time`・`needs_review`・`overdue` を返します。
画面は「読み取り: 「3/15まで」→ 2027年3月15日（日付）」のように、どの表現をどう読んだかと、要確認・期限切れの印を出します。

## 起動のしかた（手元）
Python 3.12 を想定しています（3.11 と 3.13 でもテストしています）。

```bash
python3 -m venv .venv
. .venv/bin/activate            # Windows（PowerShell）は .venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn backend.api:app --reload --port 8000
```

ブラウザで http://localhost:8000 を開くと画面が出ます。
API の説明ページ（`/docs`）は既定では出しません。手元で見たいときは `ENABLE_API_DOCS=1 uvicorn backend.api:app --port 8000` のように起動します（`.env.example` も参照）。
画面と API は同じサーバーから配信するので、他のサイトからの呼び出し（CORS）は許可していません。
`python main_api.py` でも同じアプリが起動します（同じ LAN のスマホからも開けます）。

## テストのしかた
```bash
pip install -r requirements.txt -r requirements-dev.txt
bash scripts/check.sh           # 構文確認 → ruff → pytest を1本で回す
```

Windows（PowerShell）で bash が無いときは、同じことを次の1行で行います（venv を有効にしてから）。
`python -m compileall -q backend tests main_api.py; if ($?) { python -m ruff check . }; if ($?) { python -m pytest -q }`

GitHub では push と PR のたびに、同じ検証が Python 3.11 / 3.12 / 3.13 で自動で回ります（`.github/workflows/ci.yml`）。

## 依存ファイル
| ファイル | 用途 |
|----------|------|
| `requirements.txt` | 本番（Render）が読む、版を固定した依存。`requirements.in` から作る |
| `requirements-dev.txt` | テスト・lint 用（pytest・httpx2・ruff） |
| `requirements-calendar.txt` | Google カレンダー連携の部品（`backend/task_sync/`）用。画面と API には不要 |

依存を足すときは `.in` ファイルを直して、先頭に書いてあるコマンドで `.txt` を作り直します。
